Belegter Fehler:
Nach einer bereits veröffentlichten Todesmeldung löst ein weiteres PLAYER_DEAD bei weiterhin totem Charakter erneut QueueLocalDeath aus. Es entsteht eine neue eventId, sodass der Empfänger einen zweiten Toast zeigt. Der Fall wurde in 0.11.15 und 0.11.16 reproduziert.

Implementiere eine separate modul-lokale Todeszyklus-Sperre (deathCycleActive) am Eingang von QueueLocalDeath. Prüfe/setze sie VOR CancelPendingDeath, Kontextaufnahme und NewEventId. Weitere PLAYER_DEAD desselben Zyklus werden ignoriert: kein Timer-Neustart, keine neue ID, keine zusätzliche Veröffentlichung und kein zusätzlicher Wanted-Zuwachs. Bestehende Retries dürfen ihre erste Zuordnung regulär abschließen.

Sichere Dead/Ghost-Lesung:
- ReadPlayerDeadOrGhost(): true / false / nil. API-Existenz, pcall, Secrets über Plain entfernen; nur echte Booleans.
- ResetConfirmedDeathCycle(): Sperre löschen, CancelPendingDeath, ClearDeathEvidence, NPC-Live-Flags wie beim heutigen Rez-Pfad (npcDeathActive/Boundary/Hint = false/nil/nil); npcLastDeathWall behalten.
- Beide Helfer VOR PollFalling lokal vorwärtsdeklarieren und später zuweisen (PollFalling steht vor Plain).

TryResolve (Pflicht):
Ersetze die ungeschützte Abfrage. Nicht UnitIsDeadOrGhost roh verwenden.
  if attempt > 0 and ReadPlayerDeadOrGhost() == false then
    ResetConfirmedDeathCycle()
    return
  end
Bei nil, Secret oder API-Fehler laufen die bestehenden begrenzten Retries weiter. Zeiten und Zuordnungsregeln unverändert.

PollFalling: Roh-UnitIsDeadOrGhost ersetzen; Zustand einmal über den Helfer lesen.
- nil → sofort return; Sperre und Env-Hints unberührt.
- true → return (tot/Geist).
- false → bei gesetzter Sperre einmal ResetConfirmedDeathCycle, danach Falling-Logik wie bisher.

Gib den nächsten Zyklus nur bei sicher lesbarem false frei. PLAYER_ALIVE und PLAYER_UNGHOST allein sind kein Beweis. Disable cancelt Arbeit, löscht die Sperre nicht. Enable: sicher lebend/tot/unbekannt wie im Plan. Bereits beim Modulstart tote Charaktere nicht nachmelden.
